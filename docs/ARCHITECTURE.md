# 实现说明

入口 `patch.py` 使用 Python 标准库。`route.js` 是注入到受支持应用客户端中的小型请求适配器。

## 请求路由

适配器只处理 host ID 为 `local` 的请求：

- `thread/start` 的模型为 `deepseek-flash`，且提供商未指定或为 `openai` 时，改为 `deepseek-desktop`。
- 保留动态工具、权限、工作目录及其他请求字段；DS 服务档位置空，并沿用旧补丁关闭原生 web search 的配置。
- `thread/list` 未明确过滤提供商时使用空过滤列表，使不同提供商的聊天都可列出。
- GPT、远端、既有显式自定义提供商、恢复聊天和发送回合的请求保持原值。

预热入口也应用相同路由。本机创建聊天时跳过提供商未参与匹配的预热缓存消费，避免请求已经指定 DS、实际却复用 GPT 会话。

## 构建

1. 检查 macOS/arm64、应用版本及 build、包哈希、签名与配套摘要。
2. 验证目标 ASAR 文件的完整哈希及分块哈希。
3. 三个精确修改锚点都必须唯一匹配；已打补丁或未知代码布局直接停止。
4. 复制完整应用，保留原始 ASAR 数据区域，再追加修改成员，保留共享偏移、链接、unpacked 条目和未知元数据。
5. 重算目标成员、ASAR Header、Info.plist 与 Framework 的摘要。Framework 校验槽仍为启用状态，版本为 1。
6. 本地重签副本，逐个比对所有 ASAR 成员，只有声明的客户端文件允许变更。

GPT 模型及提示词由构建时本地 CLI 读取。Flash 元数据基于本地模板设置能力字段，完整模板不会提交到本仓库。

## 安装和恢复

准备好的构建必须先通过隔离启动测试。安装要求目标应用已退出，并重新验证目标与副本，随后使用 macOS 的原子目录交换；安装后的配置和应用均再次验证。出现异常时逆向交换并恢复配置。

原始副本、交换后保留的原版、配置备份和生成模型目录留在构建目录中。恢复前检查当前应用仍是预期补丁版本，且配置未被其他操作改变。不会通过旧备份覆盖升级后的应用。

## 验证范围

CI 使用合成 ASAR 和模型元数据，测试完整性、路由、配置保留和失败回滚。它不下载或运行官方应用，不读取钥匙串，也不执行模型调用。

实际应用构建、签名、隔离启动、临时目标的安装与恢复及 DeepSeek 联网调用由维护者在 macOS 本地单独验证，记录在 [VALIDATION.md](VALIDATION.md)。
